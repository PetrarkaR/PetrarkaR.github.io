    The code, before the assembly

    The input is read two bits at a time. Try a subtraction, keep it if it fits, then append a bit to the root. Eight rounds for a 16-bit input.

    {% highlight c %} uint16_t rootf(uint16_t input) { uint16_t accumulator = 0; uint16_t extracted = 0; int16_t bitDepth = 7; while (bitDepth >= 0) { extracted = (extracted << 2) | ((input >> (bitDepth * 2)) & 0b011); uint16_t sub = (accumulator << 2) | 1; if (extracted >= sub) { extracted -= sub; accumulator = (accumulator << 1) | 1; } else { accumulator <<= 1; } bitDepth--; } return accumulator; } {% endhighlight %}

    About this version

    The instruction set, accumulator flags and I1–I10 controller states follow the project's VHDL. These are sequential controller states, not a pipeline. The browser starts after the ROM has been loaded into RAM, with the input bytes already set, at the calculation interrupt vector.

    The ROM program here is a corrected translation of square.c. The checked-in ROM gave 11 for 123, but 116 for 65535 in an instruction-level check. This version keeps both bytes of the remainder and trial divisor, and checks subtraction borrow. It has been tested for every input from 0 to 65535.

    This is a functional model, not an electrical simulation. The board's button debouncing, ROM-copy startup, RAM clock edges and seven-segment wiring are left out. RAM writes update the data byte; undriven upper bits are not simulated. The downloadable ROM hasn't been tested on an FPGA.
